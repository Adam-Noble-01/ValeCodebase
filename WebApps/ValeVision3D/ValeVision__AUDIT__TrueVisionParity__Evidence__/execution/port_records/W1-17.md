## 2. The stylesheet: why it is held back, and the proposed correction

TrueVision loads `Na__LayoutEditor__Styles__Patterns__.css` from one place only: `Na__LePanelPatterns__Register()` in
`Na__LayoutEditor__Panel__Patterns__.js` (TV :361-366, `new URL('./Na__LayoutEditor__Styles__Patterns__.css',
import.meta.url)`), which W2-29 lands. R3 C.2 (b) records it as "self-linked ... nothing to register" and forbids
pre-registering a sheet anywhere else. W0-04's G4 lint (`Na__Verify__ParityNaming__.mjs`, STYLESHEET HOMES) fails any
Layout Editor stylesheet with no home, and its baseline never holds folder or stylesheet findings.

Proof, on a throwaway root with the live verifier (`scratch/W1-17/g4_stylesheet_home_experiment.py`,
`test__g4_stylesheet_home_experiment.log`):
- A. the module + the stylesheet, nothing linking it (W1-17 as planned): **exit 1, `FAIL ... Styles__Patterns__.css
  stylesheet-home (K2 S5, R3 C.2 (b))`**;
- B. the same plus a stand-in panel linking it exactly as TrueVision's Panel__Patterns does: **exit 0, PASS**.

Landing it would therefore fail G4 on this package's own file at every run until W2-29 (a whole wave), blocking the W1
wave gate; the only other homes (the loader list, the CSS index, index.html) are hot files outside this package and
would give the sheet two homes once W2-29 lands. So nothing was written for it, and the live tree has no such file.

**Proposed orchestrator correction (OC):** move `LE/36__System__HatchPatternTools/Na__LayoutEditor__Styles__Patterns__.css`
from W1-17's `edits` to W2-29's, so it lands in the same change as the panel that links it. The ValeVision copy is
TrueVision's text with the banner token swapped (`port_w1_17.py --stage <dir>` builds it; the CSS has no console
output). Two things W2-29 will need decided:
- **Source version.** TrueVision's stylesheet carries no module version and no log (27 lines; created 20-Sep-2026 with
  the Patterns panel - TV git 62dade1c, unchanged to the pin; TV plan SitePlanComposites P7a; first devlog mention of
  the panel v2.89.0). `Na__Verify__PortNotes__.mjs` requires both an x.y.z module version and a v2.N.N app version on a
  "Ported from : TrueVision3D" note, so a truthful "unversioned" line FAILs `source-version-form` unless the PORT NOTE
  also carries a `- Legacy : <reason>` field (which turns it into a WARN). Inventing "1.0.0" would be wrong; the
  Legacy field is the honest route, or the orchestrator's ruling.
- **Header form.** Put the PORT NOTE inside TrueVision's single `/* ... */` block, before its closing rule, as
  `Na__PlanDimensions__Styles__.css` does; the G4 banner check accepts the `   VALEVISION3D - ...` line 2 (proved in
  experiment A: no banner finding).
