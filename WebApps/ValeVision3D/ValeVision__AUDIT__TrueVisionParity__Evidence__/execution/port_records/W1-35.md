## 1. Decisions taken inside the package (for the orchestrator's eye)

### 1.1 The Margin Notes description is TrueVision's whole line

TrueVision's value differs from this app's in two places: the toolbar sentence (1.17.0) and one leaderless clause ("It
lists any groups the sheet lists without leaders first (LeaderlessNote), then ..."). I took the whole line, because:
it is the one value W0-15 withheld for W1-35 (`Na__Test__AppConfigParity__` row "MarginNotes/Description, withheld,
W1-35"); no later package edits this key (W2-32 and W3-11 do not list the AppConfig), so a half-reworded value would
differ from TrueVision with no owner; the same block's `LayoutEditor__MarginNotes__LeaderlessNote`, landed verbatim by
W0-15, already documents the (inert) leaderless notes in the present tense; and the Description is a developer note -
no code in 02__Src__AppModules reads it. If Adam wants the description to describe only what is live today, the
leaderless clause can be withheld until W2-32 / W3-11 switch leaderless notes on (an AppConfig edit plus a re-owned
allow-list row).

### 1.2 Separators exactly where TrueVision 1.19.0 put them

TrueVision removed the blank line, the first separator, Undo and Redo, then Fit, 100% and the separator after them,
keeping the separator that now closes the tool group. The harness mounts TrueVision's own toolbar (git show at the
pin, its feature modules stood in) beside this app's and compares the two strips: they are equal once TrueVision's
not-yet-here controls are taken out, editable and read-only. The acceptance's "|" marks are groups, not separators:
there is no separator between Eyedropper and Snap or between Snap and the hints, and none between the read-only note
and Download PDF - in TrueVision either (its v2.124.0 proof reads "name | Select ... Ortho | Raster | Save Sheets,
Download PDF").

### 1.3 The zoom keys ship switched off, as in TrueVision

`Nav__ZoomFit` (F) and `Nav__ZoomActualSize` (1) are in `Na__Hotkeys__DrawingTabs__.json` with `"Enabled": false`,
row for row as TrueVision ships them (v2.124.0: "which still ship switched off"; F is Adam's Offset key). The harness
shows that, switched on, the real KeyMap resolves F and 1 to them, and `Controls__Pc__` runs `Na__LeNav__Fit()` and
`Na__LeNav__ZoomTo(1)` for them. Zoom to fit stays one right click away on bare paper, editable or read-only.

### 1.4 Version and the hover-text divergence

Patch step 1.9.3 -> 1.9.4 (Adam's patch-bump rule for module headers, as W0-06 and W1-34 did). The Select and Move
hover texts were a live difference the PORT NOTE did not list; this package is the one that keeps them on purpose, so
they now have their Divergences bullet (DR-40 item 7; W3-04, then W5-01).

### 1.5 The AppConfigParity allow-list now has three more STALE rows (WARN; the test passes)

`MarginNotes/Description`, `Labels/MarginToggle`, `Labels/MarginToggleTitle` (W1-35) no longer differ from
TrueVision, beside W1-34's four. The test is W0-15's file and not in my edits list, so I left it; the W1 gate can take
the seven rows off as the W0 gate did for `Pdf/JsPdfScriptPath`. Those two rows are the only `MarginToggle` text left
in the app, outside 02__Src__AppModules.

### 1.6 My own log line nearly failed the grep

The first build's log entry named the deleted labels by their key names, which a literal "grep of VVM for
MarginToggle" finds; the harness caught it before install, and the entry now says "the button's two labels". The build
script refuses any `MarginToggle` left in the file, comments included.
