## 1. Decisions taken inside the brief (for the orchestrator's eye)

a. **The Pages base is `https://adam-noble-01.github.io/ValeCodebase/WebApps`, not R3 catalogue (c)'s
   `.../WebApps/Whitecardopedia`.** Source builds its last-resort URL as `PagesBaseUrl + '/' + location.relative`, and
   W0-12's facade answers `relative` = `Whitecardopedia/Projects/<folderId>/05__Layout__DrawingDocs__Images/...` (the
   path under `WebApps/`). R3's value predates the facade and would double the `Whitecardopedia` segment. W0-12's own
   test names `PAGES_ORIGIN + '/ValeCodebase/WebApps'` as "The Sheet Images config's PagesBaseUrl" and proves
   base + '/' + relative = the repository URL; my e2e harness proves the same on the landed files (the Pages candidate
   equals the repository copy and is de-duplicated, exactly as in TV).
b. **"Fails CLOSED to no address" read as "no Noble Architecture address".** S07a-V02's recommendation for Setup is
   "Setup's PagesBaseUrl fallback is VV's Pages base"; the acceptance item is "no NA address appears with the config
   unreadable". An empty fallback was not used: Setup's `Value()` refuses '' anyway, and Source would then build a
   root-relative `/Whitecardopedia/Projects/...` URL (a seam in Source the package does not list). With VV's base the
   fallback still equals the shipped config, TV's design rule (proven: every reader answers identically with the config
   readable, 404, network error, or Flask's index.html).
c. **Source takes no `Na__CfApi__IsConfigured` import.** The package's adaptation names it, but TV's Source 1.0.0
   imports only `SheetImageLocation` and `IsRunningOnLocalhost`; adding an import would be an unlisted difference (P3).
   The facade exports `IsConfigured` (verified at :586 / :1479); Publish (W3-18) is its user.
d. **The config's PORT NOTE is a `Meta__PortedFrom` field.** JSON carries no comment, and a VVREL placeholder in a
   .json fails `Na__Verify__PortNotes__` (placeholder-code: it would reach the page), so the field names the TV path,
   Meta 1.1.0, v2.121.0, the pin, the date and "parity package W1-16", with no placeholder for the scribe. Same
   convention as VV's ScrapbookCustom and ModelLayers configs (`Meta__PortedFrom`).
e. **TV's NA examples in code comments are kept verbatim** (Geometry FolderFor comment "RB05_T01_D01", Encode
   DESCRIPTION "RB03_T01_V10__..."): K2 H4 / P3 keep TV's DESCRIPTION and comments; they never reach a Vale user and
   G4 passes. Geometry's PORT NOTE (Parity line) says so and gives the Vale form (3047_D01, DR-11). The config's
   Meta__Folders example WAS changed to 3047_D01 because that sentence had to be rewritten for the folder anyway (W0-18's
   blueprint uses the same example). Config notes citing NP03, EB03, RB05 (TV's measurements) and "the dark bronze of
   the title block" are kept verbatim - see follow-up F1.
