## 3. Execution policy for the unattended run (deviations from Section F, and why)

1. **No commits, pushes, deploys or token bumps.** Section F has Adam commit after W0-01, after W0-02 and at every wave gate. He is away, and agents never commit (F.1 P19). Instead, each wave gate saves a **checkpoint** in `execution/checkpoints/`: a cumulative binary patch against HEAD `7b4e593a` plus an archive of the new files, ValeVision and the Whitecardopedia files this programme touched only. Adam reviews and commits per wave from those checkpoints, or commits the whole tree.
2. **W0-02 (the renumber) ran before W0-01 (the decision record).** The renumber script refuses a dirty tree, and W0-01 only edits a records file whose content is fixed by the defaults above. The script's preflight ignores only this file and the two `ValeVision__AUDIT__TrueVisionParity__*` items. `git mv` stages the renames in the index, as the plan intends. Nothing is committed.
3. **Shared Vale infrastructure stays live-untouched.** W0-07 (sync purge fix), W0-08 (shared service worker) and W6-02 (precache refresh) are written as staged copies plus patches under `execution/prepared/`, with their tests run against the copies. W0-10 (worker 1.6.0) is also staged there and proven with node tests; the live worker source is not changed and nothing is deployed. Flask blueprints (W0-09, W0-18, W0-19) DO edit `WebApps/Whitecardopedia/server.py` and new `Server__ValeVision*__Api__.py` files, each validated by import and test client before saving, because Adam's running debug server reloads on save.
4. **Held until Adam answers (hard gates):** W3-04 (four gesture changes), W5-04, W5-05, W5-06, W5-07, W6-03 and the whole TrueVision lane WT-01..WT-12.
5. **Landed switched off:** the Statement Writer (`LayoutEditor__Statement__Enabled = false`, DR-10), Project QR and the title-block QR cell (DR-12), site plans dormant (DR-08), design phases dormant (DR-09).
6. **Smoke tests:** the orchestrator runs each wave's automated gates (G1 ModuleGraph, G2 Exports, G3 path gate, G4 naming / port notes once W0-04 lands, G5 node tests) and a browser smoke test in the in-app browser against Adam's running Flask server, `http://localhost:8000/ValeVision3D/index.html?project=2026/3047__Doous`. Adam's manual checklists (Section F.5.4) are still his to run.
7. **Records:** every package writes its Port Record to `execution/port_records/<wp_id>.md`. Only the wave's Parity Scribe (Wn-99) writes `ValeVision__DEVLOG__.md` and `ValeVision__PARITY__TrueVisionLedger__.md`, re-reading the devlog top first. Every TV release Adam has not confirmed is named in the devlog entry (DR-01 (c)).

- No NA content reaches a Vale user (NA URLs, `/q/` `/s/` resolvers, NA logo, TrueVision 3D Project Hub rendered, NA job phases T01-T04).

## 8. How to resume

2. Re-read the top of `ValeVision__DEVLOG__.md` and run `git -C D:/10_CoreLib__ValeCodebase status --short -- WebApps/ValeVision3D` before touching anything: parallel sessions edit this repo.
3. Brief each package from `python execution/pkg.py <id> --brief` plus Section F.6's template; after each wave run the gates, save a checkpoint (`execution/checkpoint.py Wn`), run the scribe (Wn-99), then regenerate this file (`python execution/wm.py`).
