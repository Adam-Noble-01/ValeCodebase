# Port Record - W4-15: Statement Writer stylesheets (inert, verbatim)

Status: **PARTIAL.** Both stylesheets are built from TrueVision's bytes at the pin and verified: reversing the two
header seams gives TrueVision's file back byte for byte, and every line after the header block is TrueVision's. They are
**staged and held back, not landed** in the live tree. This follows the OC-07 precedent (W1-17 -> W2-29; W3-18 -> W3-09,
ratified by OC-19). The reason: landed alone, both sheets fail G4's tree check `stylesheet-home` (K2 S5, R3 C.2 (b)) on
this package's own files. The package's acceptance requires "nothing links them until W4-12", and G4 fails any Layout
Editor stylesheet with no home. Its baseline never holds stylesheet findings.

A second problem, for W4-12 and the orchestrator: **TrueVision's own Page link does not count as a home for G4 either.**
TrueVision's Statement Page (:827-835) links the two sheets through a loop:
`for (const sheet of [ '../08__...css', '../08__...css' ]) { const href = new URL(sheet, import.meta.url).href; ... }`.
G4's home finder (`Na__Verify__ParityNaming__.mjs:497-502`) only matches a literal
`new URL('<...>.css', import.meta.url)`. So when W4-12 lands the Page verbatim, both sheets still fail `stylesheet-home`.
I proved this in a throwaway root (case B below). The fix is an orchestrator correction (see the follow-ups); this
package does not own the verifier.

Nothing in the live tree was written by this package.
