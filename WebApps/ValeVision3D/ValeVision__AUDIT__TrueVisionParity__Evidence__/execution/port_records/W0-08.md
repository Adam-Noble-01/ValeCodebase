## 3. Design choices Adam should know about (all reversible in the staged copy before applying)

1. **Token split (models and thumbnails on a token of their own).** Not named in W0-08's goal line, but assigned to W0-08 by R3 catalogue (h) "Token" (owner W0-08, W6-02), K2__TargetMaps step 4 ("DR-07's single service-worker package (cache split, unsaved-work hold, precache fixes)"), F.5.6 item 3, and W6-02's own adaptation ("models and thumbnails caches keep their own token (W0-08)"). The asset token is set to the live token, so applying the patch evicts nothing and renames nothing.
2. **Images and published buckets also ride the asset token.** Their files are content-hashed (or network-first JSON), so a shell bump has nothing to fix in them; TV puts them on its single token. To follow TV instead, change `PWA_SW_CACHE_NAME_IMAGES` / `_PUBLISHED` to `${PWA_SW_VERSION_TOKEN}` (two lines; the tests' 3.7 check names them).
3. **The new folder tests run first in the classifier.** Their folders hold nothing else; a picture whose name starts `IMG01__` would otherwise be taken by the full-image rule (pass-through), and a `.png`/`.svg` by the uncapped shell bucket.
4. **PDFs under 06__Layout__PublishedDocuments get an explicit pass-through class** (TV leaves them implicit); WCP's shell pattern differs from TV's, so the explicit rule keeps the "PDFs not cached" promise if that pattern ever grows.
5. **Sheet-picture pattern is TV's exactly** (`<folder>/<doc>/<file>.(webp|jpe?g|png)`, one level; the `00__Archive` sub-folder is not matched, as in TV).
