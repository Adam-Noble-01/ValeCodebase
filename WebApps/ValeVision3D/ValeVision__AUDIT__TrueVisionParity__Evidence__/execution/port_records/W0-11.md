## 5. Behaviour as landed (for W0-12, W0-13, W0-14 and every later TV port)

- `GetProjectFolderFromUrl()` / `GetYearFromUrl()` are synchronous, as TV's. Resolution, in order: explicit `?project-folder=` and `?year=` win (TV's parameters); otherwise both come from ONE master-index entry (`LookupIndexEntry`), the one `?project-folder=` names when given, else the one `?project=` names. A year-prefixed `?project=` must also be in the index (S12-F06: "the folder of the master-index entry for ?project ... null when the index has no entry"); it is never taken verbatim and never guessed.
- Null until `Na__AppUtils__InitMasterIndex()` has settled (explicit parameters still answer), and with an empty index after a failed fetch. Callers that need the answer must run after the index has settled (VV's LoadingSequence already awaits it; the W0-12 facade awaits it in `Initialize`).
- The year always has 4 digits. A TV-style `?year=26` reads as `"2026"`; any other malformed `?year=` gives null and one `[ValeVision3D]` console warning naming the fix.
- A folder is never answered without its year, so the TV callers' `year + '/' + folder` (Persistence, Assets, PubDoc Urls) is always a whole VV folderId, never `"null/<folder>"`; callers that build `${year}-Projects/...` (Publish, Share Manifest, SitePlan Store, ProjectQr) or default the year to `'26'` (Publish Transport) keep their own seams in their own packages, as S12 b.4 says.
- `LookupIndexEntry` stays private (not exported); the facade can build its folderId as `GetYearFromUrl() + '/' + GetProjectFolderFromUrl()`.
- On localhost, `ResolveAssetUrl(...).fallback` is the Flask copy. Today's localhost callers that read the fallback: Persistence (linework) and LE Assets (snapshots) now fall back from R2 to this disk instead of GH Pages; R2AssetUpload uses only `.primary`; the PresentationMode thumbnail resolver does not call it on localhost; LoadingSequence imports it without calling it.
