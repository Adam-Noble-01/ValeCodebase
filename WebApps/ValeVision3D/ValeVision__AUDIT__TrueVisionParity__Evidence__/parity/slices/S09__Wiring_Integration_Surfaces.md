### B2. Stylesheet registration

Three ways a drawing stylesheet reaches the page, and they differ between the apps:

1. **CSS index `@import` (eager).** TV imports 14 Layout Editor sheets eagerly (CSS index:161-174) plus the drawing dev-menu sheets, 27 ContextMenu, 54 ColourPalette (182), 55 SpellCheck (190), 47 DrawingPlanes (123), 49 ElevationDepthFog (130). VV imports only the drawing dev-menu sheets and `LE/01__Core__Loader/Na__LayoutEditor__Styles__Boot__.css` (CSS index:85-93).
2. **Loader `Na__LeLoad__STYLESHEETS` (VV only, lazy).** `LE/01__Core__Loader/Na__LayoutEditor__Loader__.js:125-134` links 8 sheets when the editor first loads, in cascade order: Surfaces (FIRST), Main, Main__Paper, Panels, Specification, Specification__Notes, Specification__Read, WebViewer (LAST).
3. **Self-linking modules.** A panel injects its own `<link>` on first mount via `new URL('./...css', import.meta.url)`: TV - Patterns (`36/Na__LayoutEditor__Panel__Patterns__.js:365`), VectorTools (`37/..Panel__VectorTools__.js:376`), ScrapbookParametric (`57/...:429`), ScrapbookCustom (`56/...:365`), FloorAreas (`59/...:733`), DrawingRegister (`51/Na__LayoutEditor__Register__Editor__.js:596`), ScrapbookSpecification (`58/...:718`), Statement + Statement__Document (`52/03__Ui__Page/Na__LayoutEditor__Statement__Page__.js:827-828`); VV - ScrapbookParametric (`57/...:178`), ScrapbookCustom (`56/...:368`).

Consequences for the port:
- **TV LE sheets that TV imports eagerly and VV does not have** must be added to VV's `Na__LeLoad__STYLESHEETS`, in TV's cascade order: after `Main__Paper` - `26__System__DraftMode/Na__LayoutEditor__Styles__DraftMode__.css`, `27__System__DrawingGrid/..DrawingGrid__.css`, `28__System__ObjectSnap/..ObjectSnap__.css`, `33__System__DrawingAxes/..DrawingAxes__.css`; after `Specification__Read` - `54__Feature__SheetImages/..SheetImages__.css`, `66__Feature__DocumentSharing/..Share__.css`; `80__Feature__WebViewer/..WebViewer__.css` stays LAST (TV CSS index:164-174).
- **Self-linking TV sheets need no registration** (port the module, the link comes with it). Watch the caching rule TV learned the hard way (B11): TV precaches its lazily injected sheets so the token governs them.
- **Non-LE feature sheets used on the start-up path must be eager in VV too:** 54 ColourPalette is imported by `43__System__PlanAnnotations/Na__PlanAnnotations__Toolbar__.js` (3D tab) and `LE/40__Ui__Panels/Na__LayoutEditor__PanelHost__.js`, so its sheet belongs in VV's CSS index (TV CSS index:182). 55 SpellCheck is only imported by `LE/58__Feature__ScrapbookSpecification/..RowEditor__.js` today, but TV registers it in the index (190) because "any text box can be a spell-checked one" - follow TV.
- **The tab strip lives in a different sheet.** TV keeps every `.na-le-tabs*` rule in `LE/10__Core__SheetSurface/Na__LayoutEditor__Styles__Main__.css` (26 matches); VV moved them, the Dev-section sheet list and the loading screen into the Boot sheet (20 matches; Boot:30-195) because the strip shows before the editor loads. A whole-file port of TV's `Styles__Main__.css` must move its tab-strip region (and any new compact-strip/drawings-menu rules from TV v2.158.0) into Boot, and delete it from Main, or the strip will be unstyled before first load and double-defined after.
- **Order differences (low risk, verify visually):** VV imports `Na__UiFeature__Styles__DevToolsMenu__.css` last (VV CSS index:112) where TV imports it right after AppHeader (TV:53, "overrides the floating dropdown geometry"); VV imports `Na__DrawView__Styles__DevMenu__.css` first in the drawing group (VV:85) where TV imports it after PlanDimensions (TV:149). The DevToolsMenu rules are scoped to `.na-dropdown-menu--dev-localhost`, so a collision is unlikely but unproven.
- **TV orphan:** `TVM/52__System__Layout__PublishedDocuments/Na__PubDoc__Styles__Main__.css` is referenced by nothing in TV (not the CSS index, not any module). Either intentionally dormant or a TV bug; do not "fix" it in VV by guessing - mirror whatever TV decides.

### B3. Layout Editor loader and facade (VV `LE/01__Core__Loader`)

What it is (Loader:13-37): the only Layout Editor module the page imports. It decides whether the editor is *offered* (Layout Mode on AND at least one sheet, read from the raw drawings block), imports the tab strip the first time the answer is yes, and imports the editor itself (ModeController, SheetModel, SpecData, ConfigState, Viewport3d, PdfExporter - Loader:244-253, literal specifiers so the module-graph harness walks them) behind the loading screen the first time something needs it. Before the load it answers the tab strip and Dev section from the raw block; after the load every facade call goes straight to the editor. It re-announces the project load once (`Na__LeLoad__AnnounceProjectLoad`, Loader:307-311) so AutoSave, History and SpecLinks get the start they missed, and it checks its copies of five event/view constants against the editor's (`Na__LeLoad__CheckNames`, Loader:284-295).

Why it matters for the port: **every TV module that TV imports at start-up, or that TV's tab strip/Dev section reach directly, must be reached through the facade in VV.**

- VV's TabStrip 1.5.0 imports only the loader (22 facade names). TV's TabStrip 2.0.0 (23-Sep-2026, TV v2.158.0, PORT NOTE "Back-port: PENDING to ValeVision3D") imports ConfigState (`GetLabel`, `FormatLabel`, `IsEnabled`), SheetModel (`CHANGED_EVENT`, `GetSheets`, `GetDrawingNumber`, `GetTabLabel`, `GetActiveSheet`, `CreateSheet`, `IsSitePlanSheet`), ModeController (`CHANGED_EVENT`, `Enter`, `Leave`, `IsActive`, `IsEditable`, `Ready`, `VIEW_SHEET`, `VIEW_SPEC`, `VIEW_REGISTER`, `VIEW_STATEMENT`, `OpenRegister`, `GetView`, `OpenSpecification`, `OpenStatements`) and SpecData (`CHANGED_EVENT`, `IsDirty`). **Facade additions needed**: `Na__LeLoad__VIEW_REGISTER = 'register'`, `Na__LeLoad__VIEW_STATEMENT = 'statement'` (TV ModeController:429-431), `Na__LeLoad__OpenRegister(options)`, `Na__LeLoad__OpenStatements(options)`, `Na__LeLoad__IsSitePlanSheet(sheet)` (answerable pre-load from `Sheet__DrawingType`), `Na__LeLoad__Ready()`, and two more `CheckNames` rows.
- VV's DevMenu imports the loader (`GetEditor`, `Require`, ...). TV's DevMenu imports `Na__LeModel__KIND_2D/KIND_3D`, `Na__LeVp3d__Bake`, `Na__LeSource__Resolve` (20 ModelSource, needs 26 PhaseLibrary), `Na__LePdf__ExportSheet`. *Verifier correction:* **do not port TV's DevMenu.** VV's DevMenu 1.4.0 (19-Sep-2026) is its own facade lineage and already reaches Bake, KIND_* and ExportSheet through `editor.viewport3d/model/pdf` after `Na__LeLoad__Require()` (VV DevMenu:221-231, 345), and it already carries TV 1.3.0's tab-label change. The only TV delta is DevMenu 1.2.0 (13-Sep-2026): a linework bake names a drawing only when `Na__LeSource__Resolve(v).isLive`. That filter does nothing until design phases exist (D-S09-07). If it is ever ported, add ModelSource to the loader's `ImportEditor` list.
- VV-only API that the loader depends on and that **TV's ModeController 1.32.0 does not export** (TV ModeController:1272-1289): `Na__LeMode__WaitForFirstDrawing`, `Na__LeMode__IsAvailable`, `Na__LeMode__IsLayoutModeOn`, `Na__LeMode__SetLayoutMode` (VV ModeController:888-902). A whole-file port of TV's ModeController must re-apply these.
- VV-only leaf `LE/07__Core__SheetData/Na__LayoutEditor__DrawingCode__.js` (pure string rules for "D03 - Elevations"; TV keeps the same three functions inside `SheetRecords__` as `Na__LeRec__ShortCode` etc.). A whole-file port of TV's `SheetRecords__` 1.39.0 must keep importing and re-exporting the leaf, or the tab strip will rename itself when the bundle lands.
- VV `42/Na__DrawView__RenameDrawing__.js:121` imports `Na__LeLoad__PrepareRestamp/RestampForScene`; TV's equivalent dynamically imports `Viewport3d` (`TV 40/Na__DrawView__RenameDrawing__.js:130`). Re-apply on port.

TV's own test `Na__Test__DraftRestore__.test.mjs` ("whichever arrives first, the project's drawings or the editor", TV v2.145.0) is the right acceptance test for this.
