# VghLantern Profile Library

Swept cross-sections traced along the skeleton construction lines produced by
`VghLantern__Geometry__SkeletonSolver__.js`. A **profile** is a section swept
along a polyline — a glazing bar running up a rafter, a ridge cap running along
the ridge. Discrete objects placed at a point (finials, vents) live in
`05__Data__LanternComponentLibrary` instead.

---

## Folder structure

```
06__Data__LanternProfileLibrary/
├── VghLantern__ProfileDataIndex__.json   ← GENERATED — never hand-edit
├── VghLantern__ProfileLibrary__README__.md
├── PRF__GlazingBars/
├── PRF__RidgeSections/
└── PRF__HipSections/
```

File naming: `VghLantern__Profile__{ProfileId}__{ShortName}__.json`

## Asset schema

Assets use the unified asset schema shared with the SketchUp
`Na__ProfileTools__ProfilePathTracer__Modules__` exporter, so a traced section
drops straight in without translation.

| Block | Purpose |
|---|---|
| `meta` | Schema version, generator, source model |
| `Na__Asset__Metadata` | Id, name, category, description, revision, material, tags |
| `Na__Asset__Profile2D` | Closed outline points in millimetres, bounding box, section area |
| `Na__Asset__Mesh3D` | Optional inline mesh — normally `null` for swept profiles |
| `Na__Asset__Glb3D__Url` | Optional GLB reference — normally `null` for swept profiles |
| `Na__Asset__Has2dProfile` / `Na__Asset__Has3d` | UI gating flags |
| `Na__Asset__SweepBehaviour` | Applicable roles, mitre behaviour, face width |

### Outline point convention — read this before authoring

Points are `{ "x": <mm>, "y": <mm> }` in millimetres, listed in
counter-clockwise winding order, forming a **closed** loop (do not repeat the
first point at the end).

- **Origin** sits on the skeleton polyline.
- **X** runs across the member, centred on the skeleton line, so a 50mm face
  spans `-25 … +25`.
- **Y** is measured from the skeleton line in the member's up direction, so the
  section occupies the positive Y half-space.

This matches the fallback outline generated by
`VghLantern__Env3d__ProfileSweep__FallbackOutline()`, so a member with no
profile assigned still sweeps in the right place at roughly the right size.

Both render environments consume the same points:

- `VghLantern__Env2d__ProfileTraceRenderer__.js` uses the X extent to draw a
  true-width band along the projected member in plan and elevation.
- `VghLantern__Env3d__MeshBuilder__ProfileSweep__.mjs` extrudes the closed
  outline along the member vector.

## Applicable roles

Each asset declares the skeleton member roles it may be assigned to. The editor
builds its dropdowns from these declarations (`OptionsSource: 'profiles:<role>'`),
so no module hardcodes a category-to-role table.

| Role key | Skeleton member |
|---|---|
| `ridge` | Horizontal ridge line |
| `hip` | Hip from ridge end to eaves corner |
| `verge` | Gable verge (shares the hip section) |

Roles that are **not** swept sections (no profile dropdown, absent from
`ROLE_PROFILE_FIELDS`):

| Role key | Why it is not a profile |
|---|---|
| `glazingBar` / `transom` | Three-part Vale glaze bar composite (`GlazeBarSystem`) |
| `eaves` | Datum ring only - not a part |
| `buildersUpstand` / `buildersUpstandPost` / `frame` | Solid prisms from `MeshBuilder__BuildersUpstandBox` |

The role-to-config-field mapping lives in one place only:
`ROLE_PROFILE_FIELDS` inside `VghLantern__AppData__ProfileIndexLoader__.js`.

## The index is generated output

`VghLantern__ProfileDataIndex__.json` is rebuilt by
`60__Dev__WebBuildUtils/VghLantern__BuildUtil__ProfileDataIndex__.py`, which
walks the category folders, reads each asset's metadata and derives the index
entry. **Never edit it by hand** — the next build overwrites the change.

Add a profile by dropping the JSON into its category folder and rerunning the
builder. `VghLantern__AppData__ProfileIndexLoader__.js` is the only consumer;
it fetches `/api/profile-index` first (served `no-store`, so the index stays
live while authoring) and falls back to the static file.

## Data status

Every example asset in this library carries
`Na__Asset__Metadata__DataStatus: "Provisional …"`. The dimensions are
representative placeholders that let the pipeline render end to end; they are
**not** verified Vale section data. Replace them with traced sections before the
tool is used for production output.
