## 1. What changed and why (one line each)

- `02__Src__AppModules/05__RenderPipeline/Na__RenderEffect__LineworkSettings__State.js` - 1.2.0: SetLineworkBaseOverride takes the viewport's nested LineworkModifier rules `[{ TagName, hidden, widthFactor, hex }]` for the same render; ApplyLineworkWidths puts every modifier node back first, then draws a matching node (leading-prefix, longest-wins, as TV) at base x widthFactor x user factor x export scale in the rule's colour on a cached per-(material, tag, hex) clone, or hides it when its row is off; clearing the override restores every node's own material and visibility. The clone also carries the loader's depth-bias onBeforeCompile hook (three's Material.copy drops it; TV's clone does too). With no rules, or no matching node, every width is exactly 1.1.0's. DR-31 (3), D-S04a-08: VV's tiled exporter re-applies linework widths from this module, so the rules must live here, not in the renderer.
- `02__Src__AppModules/51__System__LayoutEditor/25__System__RenderStyles/Na__LayoutEditor__ModelLayers__Config__.json` - TV 1.2.0 content merged into VV's file: the linework-modifiers group as `ValeVision__LineworkModifier__*`, Meta__LineworkModifiers, the storey fallback prefix, Meta 1.2.0 / SSOT 2.4.0. Inert until W2-16's ModelLayers 1.4.0 honours Group__AlwaysShow (VV 1.1.0 lists only loaded categories, so the panel does not show the group yet); EdgeStyles already reads the rows' defaults, so a model WITH 76-79 tags now gets 0.50 dark-grey / 0.25 mid-grey vectors instead of the black 1.00 fallback.
- `80__Testing__PrototypeEnvironment/Na__Test__LineworkModifiers__.test.mjs` - new VV-only fixture test (no Vale GLB carries 76-79 tags): writes a GLB with '<Tag>::<Material>' node names (duplicates included), loads it through three's GLTFLoader, upgrades lines to fat lines as the model loader does, builds the rules the way TV's Frame RasterModifiers does from the shipped configs, and checks config, owner agreement with the StageSampler, unchanged-without-tags, widths/colours per row, export-scale and user-factor re-application, row-off hiding and exact restore.

Method: both existing files were patched by Python scripts that read bytes, assert the pre-image, apply counted exact replacements and write CRLF back (`execution/scratch/W2-13/patch_linework_settings.py`, `patch_modellayers_config.py`; the config script copies TV's group / meta / fallback lines from `git show b2aa9151:...` and swaps only the app token). Pre-images are kept in `execution/scratch/W2-13/orig/`.

Fidelity check (scratch, TV config at the pin with TrueVision__ -> ValeVision__ against the landed VV config): the only differences left are VV's documented ones - the coarse Existing / Proposed rows, the legacy group, Meta__PortedFrom / WhyThisDiffers / EdgeStylesHere, and VV's pre-existing Meta__Annotation / Meta__AnnotationDraws wording (left as found; not this package's seam).
