## 5. Behaviour as landed (for W1-19, W1-22, W3-02, W3-16, W4-06, W4-07, W4-10)

- `Na__DrawData__GetDocumentCode()` - synchronous; string or null (the same contract as `GetProjectCode`, so TV's `String(project || '')` callers take it as is). Order: the loaded project.json's `projectCode` (string or finite number, trimmed) -> the `projectCode` of the master-index entry the `?project=` token names -> null. Never the folderId, never the token.
- The index fallback reads the map the ProjectLoader's memoised `Na__AppUtils__InitMasterIndex()` resolves to, asked for only once a project folder is known from the index (so it never starts a fetch of its own - proved: 0 index requests before the loading sequence's, 1 in all). The map lands a tick after the first ask: on a project.json WITHOUT a projectCode the very first call may answer null, later calls the code. Every ValeVision project.json has a code today (156/156), so the app never takes that path. (TrueVision's `?project-folder=&year=` form names a folder before the index settles; the ask then starts that same memoised load early - proved, one shared request.)
- Use it for DOCUMENT uses only: Document IDs (`{project}`), the drawing number default, the register number (`<code>_REGISTER`), PDF names, the specification number, picture folders, statement codes. Keep `Na__DrawData__GetProjectCode()` for everything that addresses storage (saves, drafts' storage keys, asset uploads, spec transport) - it is the token the facade and the local mirror resolve.
- `Na__LeRecord__Fetch()` - always a promise of `{ Client, SiteAddress }` strings from the root of the loaded project data; `Reset()` keeps its name and caches nothing.
