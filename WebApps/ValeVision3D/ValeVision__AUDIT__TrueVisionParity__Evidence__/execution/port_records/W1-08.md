## 5. Behaviour as landed (for W2-04, W2-10, W2-11/W2-16, W3-15 and every later floor plan caller)

- **The data-module convention is TrueVision's.** Every reader and writer of records goes to `Na__DrawData__GetFloorPlansArray()`; the first argument of GetFloorPlans, GetEnabledFloorPlans, GetPlanById, GetPlanForScene, NextPlanId, CreatePlan, DeletePlan, RenumberOrder and Get/SetClientDimensionsEnabled is the presentation config (TV's editors pass it) and is ignored for records; FindSceneForPlan still reads the scenes from it. Passing a drawings block, as the old VV module allowed, is now silently ignored - W2-04's re-applied VV code must not rely on it.
- **Records.** A new plan carries `FloorPlan__Dimensions: []` (VV), no `FloorPlan__StoreyLevel` and - unlike the old module - no `FloorPlan__Styles`, `FloorPlan__ExcludeCategoryTokens` or `FloorPlan__LineworkAsset` until something reads or sets them: GetStyles / SetStyle write the five style defaults on first use (TV's rule, since 10-Sep), and an absent exclusion list or asset slot reads as null everywhere (GetExcludeTokens, GetLineworkAsset, 50 Persistence's GetSlot). Records the old module saved carry all three (its normaliser wrote them on every read); no local Vale project has a floor plan record at all today (`scan_projects.py`: 156 project.json files, 0 with plans, read-only). In today's UI the 1.2.0 row builders (StyleRows' getStyles) and the mode controller's ApplyStyles call GetStyles as soon as a plan is shown, so the style keys appear as before; a plan saved before it is ever shown is saved without them (check E3/E4: every reader answers the same).
- **The storey.** `Na__FpData__GetStoreyLevel(plan)` -> `{ key, label, title, guessed, from }` (chosen, or guessed from the name, then the cut height; never written); `IsStoreyLevelSet`, `GetStoreyLevelChoices` (Ground floor, First floor, Second floor, Roof plan, Basement level), `SetStoreyLevel(plan, key)` (true when the record changed; `''` hands back to the guess by deleting the key) and `STOREY_CHANGED_EVENT = 'na-floorplan-storey-changed'` with `{ planId, key }`. Nothing in this app calls SetStoreyLevel or listens yet: the dropdown arrives with W2-04 (row builders 2.0.0 mount `Na__FpStoreyRow__Build(plan, onChange)`), the drawing title's sixth fact with W2-10 (ViewportIdentity 1.1.0 / ViewportTitleText 1.1.0 read GetStoreyLevel and listen for the event), Hide swings by storey with the LE plan-doors packages. `FloorPlanViews__StoreyLevels__Config` is VV's to reword later (labels, titles, bands) - the test keeps the shipped JSON equal to the module's built-in fallback.
