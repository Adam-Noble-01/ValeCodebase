## 1. Decisions taken inside the package (for the orchestrator's eye)

### 1.1 The drawing rows carry the drag, but not the old "Double-click to rename, drag to reorder" hover

R4 D.2.2 expected `SheetTabEditTitle` to stay in use on the Drawings-menu rows until W4-10. Its words (TV's config
value, which this app must keep: the AppConfigParity test would fail on a changed value) advertise a double-click
rename, and a menu row cannot have one - its first click shuts the menu and opens the drawing; renaming is the Sheet
panel's here (VV Panel__Sheet `sheet-name`), as TrueVision intends. So each row keeps TrueVision's hover (the whole
drawing number, and the site-plan note) and carries the drag silently in an editable session. `SheetTabEditTitle` and
`SheetNameTitle` are now unused by this app's code, as in TrueVision (both keep the keys). If Adam wants a hint on the
rows before the register lands, it needs a label of this app's own (an AppConfig key and an allow-list row); W4-10
removes the drag anyway.

### 1.2 DESCRIPTION verbatim, the differences in the PORT NOTE

K2 H4 keeps TrueVision's DESCRIPTION, and four of its bullets describe TrueVision's strip where this one differs
(shown whenever a sheet exists - here Layout Mode too; five tabs - here three until the features land; reordering is the
register's - here a menu drag until then; and TV's "Initialized from index.html"). Each difference is a Divergences
bullet, and INTEGRATION is this app's, because it states the wiring (the loader starts the strip).

### 1.3 Acceptance item 3's "at 375 px the end arrows appear" assumed five tabs

TrueVision shows the arrows only when the tabs do not all fit. Measured in Chromium (Adam's Flask server, my own tab,
in memory only): with this build's three tabs the strip fits at 375 px (scroller 367 px wide, content 367 px), so no
arrow shows - correctly, by TV's rule; at 320 px the content is 314 px in a 252 px scroller and both arrows show
(previous disabled on 3D Model), the menu clamped 8 px inside the window. TrueVision's own proof was at 375 px with five
tabs (TV devlog :1149-1150); this app overflows at 375 px again once the Register and Statements tabs land. "Next from 3D
Model opens a drawing without the menu" holds whenever the arrows show (harness C14: Activate shuts the menu and calls
Enter(null); the menu is never opened).

### 1.4 The AppConfigParity allow-list now has four STALE entries (WARN; the test passes)

`Labels/NoSheets`, `Labels/TabsPreviousTitle`, `Labels/TabsNextTitle`, `Labels/SpecificationTab` (withheld, W1-34)
no longer differ from TrueVision, so `Na__Test__AppConfigParity__` prints "WARN 4 allow-list entries no longer differ"
and still exits 0 (it fails only with --strict). The test is W0-15's file and no W1 package lists it, so I did not edit
it; the W1 gate can take the four rows off, as the W0 gate did for `Pdf/JsPdfScriptPath`.

### 1.5 The loader needed no code: two facade names are now without an importer

Nothing in TrueVision's strip asks the facade for anything it lacks, so the loader's change is its header. The old
strip was the only importer of `Na__LeLoad__UpdateSheet` (its rename) and `Na__LeLoad__GetShortCode` (its rename
field's code); both stay exported (harmless; G2 does not count importers). A later Loader holder may retire them or the
register's port may reuse UpdateSheet.

### 1.6 A cold load with the strip in view (not changed here)

Since W1-33 the strip stays visible over the boot cover during a cold load. For those seconds the strip still marks 3D
Model as the open tab (TrueVision's Enter is synchronous, so it has no such window), and a press on 3D Model is
answered false by `Na__LeLoad__Leave` while the drawing still opens when the load completes. No listed seam covers a
"pending" state, so nothing was added; follow-up 3.

### 1.7 TrueVision's comment examples kept verbatim

TV's code comment ("RB05_T01_D02 is open") and its 1.6.0 log line ("PS01_T02_D03") stay as written: source comments,
never rendered (the same precedent as W1-16's SheetImages note). The harness and the browser check used Vale-style
numbers (3047_D01 ...).
