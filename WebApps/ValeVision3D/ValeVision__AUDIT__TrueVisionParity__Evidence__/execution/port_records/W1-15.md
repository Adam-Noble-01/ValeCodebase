## 1. Decisions taken inside the brief (for the orchestrator's eye)

a. **The resolver key is the master-index entry's `qrKey`, read through the loader's memoised index.** The package
   says "resolver key per DR-12"; DR-12's default (A) only switches the system off, and its recommendation (the one
   K1 and S07a-F29 spell out) is a permanent `qrKey` per master-index entry. W5-05's edits list does not include
   ProjectLink, so this file must already read what W5-05 will write: it does, and answers `''` until then. The entry
   is reached through `Na__AppUtils__InitMasterIndex()` (exported by VV's ProjectLoader; it resolves the
   `byFolderId` map) because ProjectLoader exports no entry accessor and is not in this package's edits. The ask is
   made only once W0-11's helpers already answer a folder - i.e. once that memoised index has settled - so the link
   never starts a fetch of its own; a Module Start read means the first sheet painted already has the key.
b. **`projectCode` in VV is the resolver key, not the human project code.** In TV the two coincide (PS01). Keeping
   one meaning keeps BuildUrl, CurrentUrl and Symbol.VerifyEntry (which looks the code up in the resolver's index)
   TV's line for line. Consequence for consumers: see follow-up F4.
c. **IsEnabled is `config read && Enabled === true`.** The minimal fail-closed form would have been
   `!!config && Enabled !== false`; the strict form also keeps a code off when some other JSON answers (a stale or
   foreign file without the key). W5-05 writes `true` explicitly, so it changes nothing there.
d. **The FALLBACKS stay empty for good, not until the resolver exists.** `Na__ProjectQr__Text()` reads an empty
   `BaseUrl` in the file as absent and falls back: with TV's fallback, VV's shipped `""` would have printed TV's own
   resolver address. Recorded in the Symbol PORT NOTE and the README so W5-05 does not "restore parity" there.
e. **The test's stand-in addresses.** Section 2 proves TV's address rules on the address DR-12 names as the Vale
   candidate (a `q/` page on ValeCodebase's GitHub Pages - shipped nowhere, nothing resolves it yet), which also gives
   Adam the real Vale numbers (52 B, version 4, 0.270 mm). Section 7's switched-on case uses
   `https://qr.example.test/q/` (the reserved .test domain) and a stand-in key `test-key-3047`; nothing real.
f. **TV's examples inside verbatim code are kept**: the Encoder's code comment "PS01's 29 x 29 symbol holds 436 dark
   modules" (as W1-16 kept TV's examples in comments; reaches no user; G4 passes). Every adapted file, the README and
   the tests carry no PS01 / MustersRoad / NA address (checked by the port script).
g. **Two scratch tools are now outside the repository by default**: the port script's dry-run builds and diffs (which
   quote TV's lines, NA addresses included) go to `<OS temp>/W1-15__port_out`; the first build's copy was moved to
   the session scratchpad. TV's files were read at the pin into the session scratchpad only.
