## 5. Behaviour as landed (for the W2-99 scribe and the smoke test)

- **Every tick ends in `Na__RenderLoop__ArmNextFrame(keepRendering)`**, from the tick's finally (after `Na__InteractiveOverlays__EndFrame()`): hidden tab -> nothing; `WatchRefineProgress()` on every path; keepRendering -> next frame; else the refiner's pending work (straight back mid-burst, or the settle wake-up); else a part-finished total with nothing scheduled is restarted after 1 s (`Na__RenderLoop__STRANDED_RECOVERY_MS`), which a resting refiner (0 or converged) never triggers.
- **A frame that throws** is caught and reported once per frame: `console.error('[ValeVision3D] Render frame failed; the loop carries on:', error)`. keepRendering is false for that tick (TV's choice), so an interactive drag continues on its next input event; a refinement burst continues from where it stopped.
- **The watchdog**: a sample count that has not moved for 2.5 s (`Na__RenderLoop__NO_PROGRESS_MS`) prints `[ValeVision3D] Progressive refinement stalled at k of 16; restarting the run.` with { wanted, delayMs, fps, readBuffer WxH, pixelRatio, dpr, activeReasons, trailing, held, hidden } and restarts the run. Silent in every healthy scenario the harness ran.
- **The engine hold**: `RenderFrame` begins with `if (Na__RenderLoop__IsPaused() || Na__RenderLoop__PauseReasons.size > 0)` -> remember the frame, `suspend()`, return false. ValeVision's own hold set, ScheduleFrame's refusal and the pause / resume listeners are unchanged; the tick's former early return is gone (its job is the gate's). The Invalidation mirror closes W1-01's follow-up 3 (a hold taken before the loop's listeners existed).
- **planFrame** is called with `{ camera : Na__RenderLoop__ActiveCamera, sceneBusy }` - no `now`.
