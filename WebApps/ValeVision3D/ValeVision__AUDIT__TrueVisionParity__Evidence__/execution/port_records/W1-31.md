## 1. Decisions taken inside the package (for the orchestrator's eye)

### 1.1 CheckNames rows for names the editor does not declare yet - ordering defect, proposed correction (F1)

K3 puts the facade (W1-31) before the mode controller realignment (W1-32 depends on W1-31), and W1-31's goal asks for
the view-name copies "with CheckNames rows". But W0-04's G2 pass 3 proves every `editor.<part>.Na__<Name>` the loader
reads is exported by that part's module. VV's ModeController exports no `Na__LeMode__VIEW_REGISTER` /
`VIEW_STATEMENT` until W1-32, and VV's SheetModel no `Na__LeModel__DRAWING_SITEPLAN` until W1-21. A direct row now
fails G2 on the loader (my own file); reading the constant by string to slip past pass 3 would defeat the gate, so I
did neither. What landed instead:

- the copies themselves, checked by the new test against TV's constants at the pin (and against VV's the moment VV
  declares them);
- a CheckNames comment saying the row joins in the change that declares the constant;
- a test check that FAILS once VV's editor declares a copied constant whose row is missing, naming the exact row.
  Simulated on a scratch copy of the app (OS temp, never the live tree): with W1-32's two constants added to the
  mode controller the test fails 2 checks ("add [ Na__LeLoad__VIEW_REGISTER, editor.mode.Na__LeMode__VIEW_REGISTER,
  'the register view name' ] ..."); with the two rows added it passes 118/118 and G2's facade count becomes 37 with
  no facade failure.

Proposed correction (OC-style, at dispatch): the first Loader holder after W1-32 - W1-33 - adds, inside
`Na__LeLoad__CheckNames` after the VIEW_SPEC row (the row list is CRLF):

```
            [ Na__LeLoad__VIEW_REGISTER,  editor.mode.Na__LeMode__VIEW_REGISTER,  'the register view name'   ],
            [ Na__LeLoad__VIEW_STATEMENT, editor.mode.Na__LeMode__VIEW_STATEMENT, 'the statements view name' ]
```

(the VIEW_SPEC row gains a trailing comma) and drops "the register and statement views until the mode controller

removes the rest of that clause. If neither happens, the wave's G5 run of Na__Test__LoaderFacade__ fails with the
row to add - by design.

### 1.2 OpenRegister / OpenStatements land refusing; the forwarding comes with the feature

R3 C.2 (a3) and S10: "stubs returning false until the features land", owner "W1-31 (live W4-10, W4-13)". The bodies
call only `Na__LeLoad__RefuseView(view)`. The package that lands a feature flips its `Na__LeLoad__FEATURES` entry
and, in the same edit, forwards the entry point through `Na__LeLoad__WithEditor((editor) =>
editor.mode.Na__LeMode__OpenRegister(options), false)` (OpenStatements the same). Two guards keep a half-done flip
visible: RefuseView logs a console.error when the map says present, and the test's static check C fails unless a
present view's entry point forwards to an export the mode controller has. W4-13 must also make
HasFeature(VIEW_STATEMENT) honour `LayoutEditor__Statement__Enabled` (DR-10) - HasFeature is a function so that
can be added there.

### 1.3 IsSitePlanSheet: TV's rule on both sides of the load (R3 wording "after load answer false" not followed literally)

R3 C.2 (a3) says "after load answer false while the editor lacks Na__LeModel__IsSitePlanSheet". The package
acceptance says "the facade answers identically before and after the first editor load", and the loader's founding
rule is that a tab must not change when the bundle lands (TV TabStrip 2.0.0 gives a site-plan row its own class and
hover). Answering false only after the load would change a site-plan row as the editor arrives. So the facade
applies TV's own rule (`!!sheet && sheet.Sheet__DrawingType === 'siteplan'`, TV SheetRecords :1311) to the record
it is handed, before and after; VV's normaliser keeps the field in place today, and TV's (W1-19) keeps 'siteplan'.
No forwarding to `editor.model.Na__LeModel__IsSitePlanSheet` (G2 would fail until W1-21; the rule is identical).
"False in VV" (R4, S10) still holds in practice: no VV record carries Sheet__DrawingType (DR-08 (B), dormant).

### 1.4 Ready: settles with the first load, never causes one

S10's verifier lists Ready as "not needed" by the strip (W1-34 drops TV's `Ready().then(Render)`); K3 lists it, so it
is provided with a definite meaning: forwards to `editor.mode.Na__LeMode__Ready()` once loaded; `false` once the
editor's config is known to have it off; otherwise a pending promise settled by the first load (true started,
false off or failed). The same answer whether asked before or after the load (test: before -> pending -> true after
the load; asked after -> true; config off -> false both sides; failed load -> false). A caller that needs the
editor calls Na__LeLoad__Require.

### 1.5 Module versions: patch steps

Loader 1.1.0 -> 1.1.1 and LoadingScreen 1.0.0 -> 1.0.1, following Adam's written rule (memory note
devlog-entries-use-patch-bumps: per-file DEVELOPMENT LOG headers step the patch number) and this run's precedent
(W0-11, W0-12, W0-13, W1-01, W1-03, W1-04). The plan's title "Loader facade 1.2" is a label; Adam can relabel.

### 1.6 Loading-screen wording

Title only, to TV's VeilDrawingsHeadline fallback, plus the drawing-count label read through GetLabel - the
"wording aligned with the LE config veil labels" of the package. W1-33's brief also lists "TV headline" among its
LoadingScreen hunks: it will find the title already TV's; the restyle, the Title Case pre-load lines and
`Na__LeLoadScreen__IsShown` remain W1-33's. Q-COVER (1) default holds: a cold document-tab press shows the same
headline with VV's two pre-load lines.
