## 8. Issues for the orchestrator

1. **A pre-existing identity leak no package owns keeps the ParityNaming baseline non-empty.** `02__Src__AppModules/51__System__LayoutEditor/80__Feature__WebViewer/Na__LayoutEditor__Styles__WebViewer__.css:2` still carries TrueVision's banner, `/* REGION  |  TrueVision3D - Layout Editor Web Viewer Styles */` (K2 H1; the other 13 stylesheets of that header style read `ValeVision3D`). The plan's grep looked for upper-case `TRUEVISION3D` and missed it, and no package in `wp_canonical.json` lists this file. Following C13's rule (the baseline "holds every pre-existing hit ... recorded on the tree W0-04 lands on") it is held as a WARN, but the W0 exit condition wants an empty ParityNaming part at W0-99. The fix is one token on that line (`TrueVision3D` -> `ValeVision3D`); whoever applies it takes the file off the baseline automatically and the lint then passes with no warning. Until then the lint passes with this one WARN. (The plan's own expected entry, SpecPdf:147, never reached the baseline: W0-12 removed the read first.)
2. **The baseline was recorded at 01-Oct-2026 20:34 while W0-12, W0-14, W0-16, W0-19 and possibly others were still landing.** A file any package writes after that is held to G4 in full (C13's intent). If an in-flight W0 package wrote pre-H5 PORT NOTEs (no Source version line) or left a mixed log after 20:34, PortNotes will FAIL on it at the wave gate. Either that package's PORT NOTE gets its Source version line, or - if the integrator decides the in-flight W0 packages predate the gate - the baseline is re-recorded with `python execution/scratch/W0-04/record_baseline.py` (it prints the ParityNaming hits it would hold; check that list is only issue 1 before keeping it).
3. **Interpretation: the DEVELOPMENT LOG block is treated as history, like the PORT NOTE block.** A whole-file port takes TrueVision's log verbatim (DR-34 (a), K2 H6), and those logs name TrueVision's literals: W0-15's ports already carry `TrueVision__DrawingNotes__.json` (`LE/03__Core__Config/Na__LayoutEditor__ConfigState__.js:140`) and `['TrueVision__Linetype__DoorSwings']` (`ConfigState__SheetSetup__.js:62`), and W0-03's Port Record (follow-up 4) asked for exactly this ruling. The block is bounded the same way as the PORT NOTE (to the next rule line or the first non-comment line), so no code can sit inside it. Without it those two lines FAIL and every later whole-file port with a TV log would too.
4. **Interpretation: the test folder is held to the banner rule only.** Parity tests and these gates read TrueVision's tree and name its tokens, paths and markers as data (W0-15's `Na__Test__AppConfigParity__.test.mjs` has seven such lines; TV's tree path itself contains `TrueVision__`). K2 H1/C1 scope their rules to "VV src or styles"; a TrueVision banner in a test file still fails.
5. **PortNotes log order: newest first is required in folders 40-55 and in every file whose PORT NOTE names a TrueVision source; elsewhere a log may run oldest first if it keeps to it.** Many of this app's 3D-tab logs run oldest first by convention; holding them to S11's "descending" wording would have baselined ~170 entries of noise. A mixed or repeating log fails everywhere.
6. **G4-UI blocking is per check (`--block`), not automatic.** The script does not read the execution state; the integrator adds checks as their owners finish (section 6).
